# Wayfinder Map: Dataviz Portfolio Project — Financial Data, Answered Well

Labels: `wayfinder:map`
Status: open

## Destination

An **original financial/market-data visualization project** — researched, chosen, then built — that makes a visitor immediately think: *"This person knows data, visualization, frontend engineering, interaction design and storytelling."* Not a generic chart-dashboard. The finished project enters Naman's portfolio as its engineering-and-data proof.

**This map's discipline: research first → choose second → architect third → code last.** No implementation tickets exist until Naman answers the decision questions and picks a direction.

## Notes

**Core principle**: Find a question about financial/market data interesting enough to deserve an interactive visual explanation, then answer it exceptionally well with data + visualization + storytelling + engineering. Never "a really nice stock chart."

**Anti-goal**: generic finance dashboard assembled from chart components; novelty for novelty's sake.

**The project should demonstrate**: data acquisition, cleaning/transformation, modeling, visual encoding, interaction, frontend engineering, information hierarchy, storytelling, responsive design, thoughtful interaction, potentially backend/API work, maintainable architecture.

**Research-team structure (no sub-agents in this harness → parallel research tickets)**:
1. Dataviz education — The Pudding (data/design/storytelling), Andy Kirk, Observable, D3
2. Visual references — 15–25 analyzed projects (strict per-project format)
3. Financial APIs — 5+ providers, licensing vs. access distinction, verification over assumption
4. Architecture — D3 + vanilla, Node/SQLite viability on ephemeral hosts, hosting reality
5. Concepts — 8–12 genuinely different project concepts, grounded in streams 1–4, then strongest five + decision matrix
6. Synthesis → single report → questions to Naman → **stop; Naman chooses**

**Evidence discipline**: every claim cites its source; distinguish Source evidence / Researcher's interpretation / Project recommendation. Licensing: "free API access" ≠ "permission to publicly display the data" — if unclear, mark *Needs legal/terms verification*.

**Skills to consult**: `research` for streams 1–4; `grilling` + `domain-modeling` for the selection decision; `prototype` later for concept sketches if needed.

## Question

Which AI-generated-web patterns do we watch for, and how do we make the portfolio's visual language its own? Input: a 30-point anti-pattern checklist (harsh gradients, default iconography everywhere, pure-white genericism, purposeless rainbow color, excessive shadows, three-feature-cards-in-a-row, decorative emojis, liquid-glass defaults, unnecessary em dashes, default Inter/Geist/Space Grotesk, colored-left-stripe cards, fake testimonials, default bento grids, decorative terminals, "It's not X, it's Y" copy, generic checkmark lists, three-tier SaaS pricing cards, fake demos, excessive rounding, purple-and-black AI aesthetic, skeleton loaders, radial orbs, dot grids, sparkle icons, purposeless animated arrows, fake ToS/Privacy, gratuitous hovers, unjustified neon, generic pastel blocks). **Validate and refine** the checklist rather than treating it as unquestionable truth: research which of these are genuinely reliable AI-fingerprints, which are legitimate techniques with bad defaults, and what the current web-design clichés actually are. The rule to encode: *don't use a pattern because AI commonly uses it; use it because the content, brand, interaction, or visual system requires it.* Also: don't replace the AI aesthetic with an equally predictable "anti-AI aesthetic." Combine with an originality framework — study Godly.design, Variant.com, Watermelon UI for typography, composition, color, navigation, image treatment, motion, section rhythm, density, transitions (principles, not templates), then deliberate divergence. Deliver a validated anti-pattern watchlist plus an originality/divergence framework, tagged Evidence / Convention / Taste / Project constraint.
